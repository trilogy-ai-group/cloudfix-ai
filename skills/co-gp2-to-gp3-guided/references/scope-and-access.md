# Scope, access and inputs

Read this at stage 1 of `SKILL.md`, before any AWS read. It holds the complete rules for profile and scope, the access order and charges, the assessment inputs, supplied evidence, run metadata and discovery coverage. Stage numbers refer to `SKILL.md`; the other files named here are in this `references/` folder.

## Profile and scope

If the harness keeps a local profile file, such as `.claude/skills/_profile.json` in its working directory, read it for an existing AWS profile/region. A profile is optional. User-supplied account, region and tools take precedence. Keep credentials in the customer's existing harness. No data is sent to CloudFix by this skill.

Confirm the requested account and region from the user's scope and the existing authenticated tool context. Use read-only AWS access for assessment; simulations use only their supplied evidence. Do not expand to other accounts or create resources for a demonstration. Preserve raw responses, timestamps, configuration and price provenance in a local evidence record. Do not record credentials.

The observable result is: which candidates were inspected, each check's evidence and result, the proposed gp3 settings and cost estimate where justified, and any missing information. Actual execution and observed savings are separate from the assessment: `execution_status` stays `not_executed`, and an estimate is not an observed saving. Assessment-only requests end after the report. Requests that also ask how to apply it continue to a proposed PR or AWS procedure in stage 6. This skill never executes it; execution is the customer's own action under their own authorization.

## Access, cost and confidentiality

Before a live run, state the required actions: `sts:GetCallerIdentity`, `pricing:GetProducts` in `us-east-1`, `ec2:DescribeVolumes`, and `ec2:DescribeInstances` when attached-instance evidence is needed. Billing estimates additionally require `ce:GetDimensionValues` and `ce:GetCostAndUsage`; a separate existing billing profile is allowed. No GitHub access or CloudWatch metrics are needed for assessment. Do not create IAM permissions, enable billing settings or provision infrastructure.

Choose the requested price basis: public list prices, supplied costs, or Cost Explorer billing estimates. If unspecified, resolve that choice once. Disclose approximately $0.02 for two successful unpaginated CE requests, with more for pages/retries. An explicit billing request or earlier authorization covers those calls. Billing still requires public Pricing data because the finder estimates the GP3 target through the public GP3/GP2 ratio. A billing error does not authorize switching to public-price savings, unless the customer's own request allowed that fallback (see `assessment-guide.md`).

Match the code-based access order: verify STS identity and the expected workload account, perform the four required Pricing lookups from `pricing.md`, and **select and validate their dimensions, units, rates and any source-defined fallbacks now**, before volume inventory. Saving raw Pricing responses is not price validation. Reuse the resolved prices rather than repeating queries. Immediately before a needed EC2 inventory/instance read, make a scoped `DryRun=true` request with the same inputs when the harness exposes that operation. The expected `DryRunOperation` error means authorized; any denial is an error with exact action/profile/region/input retained. If the available tool cannot expose dry-run, disclose that limitation and use the actual authorized read; never claim a preflight was performed. There is no additional paid CE permission probe. After nonempty inventory, check that every selected volume has a finite positive live Size, then calculate `publicAnnualCost = Size * gp2.storagePrice * 12` for every selected ID. Before either CE call, save the frozen scope, observation clock, configuration, exact sizes, resolved rates, unrounded public baselines and timestamped provenance in the evidence file `evidence/pre-billing-snapshot.json` (the same content is the `resource_collection` of the optional replay packet in `native-output.md`). These are worker checks; no independent review is required before CE. For recorded input, use supplied evidence without AWS calls.

Keep complete raw responses, calculation records and results private: they may contain account IDs, private IPs, key names or billing data. Redact public excerpts only. Do not send evidence to CloudFix or publish it in GitHub issues. Your harness/model settings govern its handling of the data; never record credentials.

No candidates skips CE. Public-price, supplied-cost and billing runs all use the same verification stage. Recorded CE input may be processed without new calls; unproved historical sequencing remains unverified. A documented source-defined price fallback is allowed, but is not an independently retrieved price.

## Assessment inputs

Obtain these inputs for each selected resource:

- Account, region and volume ID; complete volume and required instance responses, including all pages.
- A declared assessment time. Use the current time for current infrastructure; use the supplied fixed time for a simulation. Never relabel historical evidence as current.
- `volumeAgeThreshold`: integer >= 0; source schema default **7** days. `minimalSavings`: the source framework reads `MINIMAL_SAVINGS`, default **0**, in annual currency units. Use explicitly supplied assessment settings when provided; do not claim to know a tenant's overrides. Invalid supplied configuration is an input error, not permission to silently use defaults.
- Volume `Size` in GiB; annual current cost (`annualCost`) and annual public cost (`publicAnnualCost`), with source, period and currency; resolved gp2/gp3 monthly prices described in `pricing.md`.

The local adapter always evaluates dates in **UTC** and defaults to age 7 / minimum annual savings 0; do not import process environment or tenant overrides. Only explicit `volumeAgeThreshold` and `minimalSavings` override these defaults.

The shared schema also declares `lookbackPeriodInDays=14` (allowed 7/14/30/60), `utilizationStatistic=MAX` (allowed `P95`, `P99`, `MAX`, `AVG`) and `metricsBufferPercentage=20` (0–50). **This gp2 validator does not use those three settings.** Do not gather metrics, add a buffer or change the sizing formula merely because those fields exist.

If an input response has not been supplied, request the relevant read and its parameters. Do not create an empty response to make the calculation run. Missing response, successful empty response, malformed data, access denial and a completed negative assessment are different outcomes. This evidence-request behavior is the harness workflow, not an additional validation in the original finder.

## Supplied evidence, replay input and retry

For supplied evidence, preserve the adapter's input contract: a 12-digit `accountId`; AWS-shaped region (`^[a-z]{2}(?:-[a-z]+)+-\d$`); timezone-aware ISO `asOf` if supplied; a nonempty resource array with nonempty IDs and finite nonnegative numeric `annualCost`/`publicAnnualCost`; gp2 and gp3 resolved prices with finite nonnegative numeric `storagePrice`, `iopsPrice`, `throughputPrice`, `freeIops`, `freeThroughput`; and response records with operation `DescribeVolumes` or `DescribeInstances` plus object `input`/`output`. Configuration allows only age integer >= 0 and finite minimum savings. Extra evidence keys beyond `asOf`, `accountId`, `region`, `resources`, `prices`, `responses`, `configuration`, extra resource/configuration/response keys, or extra top-level price types are input errors. Extra metadata belongs in `run_context`. Preserve it, including on errors. AWS timestamp fields, when non-null, must parse as dates.

A completed live empty inventory is a separate successful outcome, not a raw replay packet with missing resources. A supplied `{evidence, run_context}` packet must preserve both. Merge configuration from these two places only when they agree; retain original input, source timestamp, pricing provenance and any prior billing failure. A saved billing failure remains failed on replay. For retry, use the same original account, region, selected IDs, sizes, prices and observation time; retain all previous failed and successful reads instead of collecting another resource snapshot silently. When a replay packet is requested, use the exact replay field names in `native-output.md`; aliases are not interchangeable with the native reader's keys.

## Run metadata and experiments

Create one shared run-metadata object before saving any input: `accountId`, `region`, `asOf`, `configuration`, `configuration_overrides`, `run_classification`, and `experiment`. For ordinary live/replay use `run_classification: "standard"`, `experiment: null`, and `configuration_overrides: {}` at defaults. A request to test the skill on unchanged live evidence is an ordinary assessment; it is not automatically an experiment. For an explicitly marked experiment use `"experimental"`, preserve the nonempty `experiment.reason` and **all** extra caller-supplied fields, and record actual overrides as a key/value object against defaults 7/0. Never change assessment rules just to label a test.

Save this object once in `assessment.json` as the run-level `details.run_metadata` (see `assessment-guide.md`). State the classification and any experiment or overrides in the customer report. Copying it into every other saved file is part of the optional replay contract in `native-output.md`.

For explicitly requested experiments, preserve the shared metadata in every report, saved input, retry and replay. Conflicting inherited/new reasons or conflicting configurations are input errors. A normal replay, live test or legitimate nondefault configuration alone does not imply an experiment. Do not alter the seven-day rule unless explicitly requested. Preserve original files and label test outcomes; do not repair output to claim a pass.

## Discovery and its exact scope

When the user supplies candidate IDs, assess those IDs. For a live inventory, the harness can use `DescribeVolumes` with `volume-type=gp2`, collect all pages and report the inspected scope/count. This is a **replacement for CloudFix's CUR discovery stage**, not identical coverage. When only a subset is assessed, identify the unassessed remainder. A completed, correctly scoped, fully paginated GP2 inventory with no volumes succeeds as “No GP2 volumes found”, with no CE calls. A missing, denied or unfinished inventory is not empty.

The source CUR stage selects AmazonEC2 `%VolumeUsage.gp2` records with gp2 volume type, resource IDs matching `%vol-%`, nonempty region, excluding Tax/Credit/Refund. Its 31-day window is **[UTC midnight 32 days ago, UTC midnight one day ago)**; annualized cost is `round(sum(cost) / 31 * 365, 2)`. It requires the latest usage end to be strictly newer than seven days, annualized amortized cost strictly above the effective tenant discovery threshold, an allowed region from the configured region set, and a null/empty `resource_tags_user_cloudfix_dont_fix_it` aggregate. A nonempty `cloudfix:dont_fix_it` CUR tag excludes the candidate. These are **discovery filters**, not checks performed by the gp2 validator. The pipeline uses a finder-specific override when defined, otherwise `tenant.resourceCostThreshold`; GP2 has no such override. A database default is not evidence of the actual tenant setting. Do not impose a guessed threshold on direct inventory. If CUR, tenant threshold, configured region set or tag history is unavailable, report those discovery conditions as unchecked. Do not invent that context or claim pipeline discovery parity.

# Change proposal

Read this when the customer accepts the offer that ends the assessment, or asks for a change proposal. The assessment itself never needs it. A proposal is a separate document.

The source fixer adds owner-level permissions through UpdateDashboardPermissions, UpdateAnalysisPermissions, UpdateDataSetPermissions and UpdateDataSourcePermissions for the supplied lists, in that order. It uses GrantPermissions, does not revoke existing permissions, waits 10 seconds, then calls **DeleteUserByPrincipalId** for the source PrincipalId/account/default namespace. It makes no direct asset-delete calls. These are separate non-atomic operations with retries and **no rollback**; failure can leave earlier grants in place. Do not describe this as a complete asset move or guaranteed preservation.

User deletion permanently removes user metadata. The four arrays do not establish that all assets, folder/access relationships, group/IdP assignments or conversation history are covered. [AWS lifecycle documentation](https://docs.aws.amazon.com/quick/latest/userguide/user-lifecycle-data-handling.html) distinguishes console deletion (sole-owned assets may be deleted without transfer) from DeleteUser API (assets may remain orphaned). It does not establish equivalent residual-asset handling for **DeleteUserByPrincipalId**. Verify that exact API path and all unselected assets/recovery/retention before execution; do not claim all untransferred assets are deleted, recoverable, or transferred. This operation does not delete the IAM or Identity Center identity.

The assessment itself changes nothing. When the customer accepts, prepare the proposal as a separate procedure with exact account/region/user ARN, receiver, complete asset selection, estimated savings basis and unresolved prerequisites. Independently establish owner intent, retained access, receiver suitability/permissions, retention/compliance needs, asset recovery and infrastructure-management ownership; these are change prerequisites, not extra native finder tests. An account-admin role, native idle inference or receiver event alone does not approve removal. Execution requires a separately authorized, reviewed concrete operation and fresh state.

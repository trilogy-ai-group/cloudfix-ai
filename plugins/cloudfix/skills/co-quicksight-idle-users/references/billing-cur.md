# Billing mode: native CUR discovery and annual cost

Read this at stage 2 of `SKILL.md` only when the customer supplies a CUR table for a billed-cost request (`scope.pricing_mode:"billing"`, `costs.basis:"resource_billed"`) or asks for native CUR discovery. Otherwise skip it: a billed-cost request without a supplied CUR table uses `billing-cost-explorer.md`, and a customer is never asked to create a CUR.

For CUR, use the customer's known table and matching schema; never guess payer, database or table. Record the query, schema/table identity, query ID, scope predicates, all pages and UTC bounds. Substitute recorded `asOf` for the current date on replay and derive live bounds from the frozen evaluation date. Add authorized account/resource predicates. Native groups by **billing product_region** and only afterwards extracts the user's region from its ARN; do not filter only by product_region when that would discard the selected ARN's billed rows.

1. Select `line_item_product_code='AmazonQuickSight'`, **`line_item_line_item_type='Usage'`**, and `line_item_operation LIKE 'QS-User-%'`. Usage-start bounds are inclusive `date_trunc('week',CURRENT_DATE-INTERVAL '31' DAY)` and exclusive `date_trunc('week',CURRENT_DATE-INTERVAL '1' DAY)`. Weeks start Monday. This is not a rolling 30-day window: at 2026-11-17 UTC the bounds are **2026-10-12 through 2026-11-16 exclusive**, 35 days.
2. Group by `line_item_resource_id`, `line_item_usage_account_id`, `product_region`. Sum public cost from `pricing_public_on_demand_cost`. The native amortized CASE's only reachable branch under the Usage filter is **`COALESCE(line_item_net_unblended_cost,line_item_unblended_cost)`**. Preserve SQL null semantics; zero net cost is not missing. Missing required schema columns are an evidence gap, not permission to use a different basis. The unreachable native CASE includes SP/RI fee/usage/credit/refund/tax branches; do not widen the filter to include them. In particular its noncurrent SP recurring expression is `total_commitment - used_commitment * (1-discount/unblended)`, not EBS's differently parenthesized expression.
3. `annualCost=ROUND(SUM(amortized amount)/30*365,2)` and `publicAnnualCost=ROUND(SUM(public amount)/30*365,2)`, **retaining divisor 30 regardless of actual window length**. Name is `MAX(COALESCE(resource_tags_user_cloudfix_name,resource_tags_user_name,''))`. Exclude a group unless `MAX(resource_tags_user_cloudfix_dont_fix_it)` is null or empty. Native final discovery requires annualCost **>= tenant resource-cost threshold**. The pipeline selects `THRESHOLD_MAP_OVERRIDE.get(finder) ?? tenant.resourceCostThreshold`; this finder has no override. Use the actual supplied tenant value to claim native discovery parity; otherwise mark it unverified. Do not infer a tenant's value from a database default. There is no additional latest-usage, nonempty-ID or nonempty-region filter in this query.
4. Parse region using case-insensitive `(?:arn:aws:quicksight:)([a-z0-9-]+)(?::\d+:user\/)`; use captured region when it matches, otherwise billing region. Only an exact empty resource name falls back to the ARN's final slash component. Preserve ARN identity and original billing region. After parsing, native discovery keeps only parsed `awsRegion` values in `(AVAILABLE_REGIONS ?? 'us-east-1').split(',')` plus literal `global`. Unknown deployment region configuration means unknown native discovery parity. This is separate from DescribeRegions activity coverage and the user's authorized standalone scope. A selected ARN absent from the query does not establish zero cost.

This is historical billing annualization. `publicAnnualCost` is retained but unused by the savings formula. Differences in dates, discounts, configuration, tenant threshold, allowed discovery regions or source revision can change a CloudFix comparison.

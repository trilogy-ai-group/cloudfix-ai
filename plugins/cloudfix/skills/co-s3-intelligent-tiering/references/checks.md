# Analysis: the ordered checks

Read this in stage 3 of `SKILL.md`. It gives the finder's twelve checks in order, each with its exact pass rule, value object and failure type, plus the lifecycle rule helpers, the archive-configuration branch, the control flow after a failure and the exception contract. Orders 9–12 take their inputs from `references/costing.md`. `references/assessment-guide.md` says how each outcome is saved.

Initialize each row with `approved=undefined`, `stopProcessing=false`, `annualSavings=0`, empty validations/report data, and parameters `{resourceId, bucketName:resourceId, sitRuleName:"CloudFix-Standard-To-Sit"}`. A **fail-fast** failure sets `approved=false, stopProcessing=true`; every later validation, including savings gates, is skipped. An ordinary failure sets `approved=false` but later validations continue. Passing an ordinary row does not erase prior failure. Record exact value objects below; undefined properties are omitted when JSON is serialized. Preserve full objects, not truncated summaries. A check a fail-fast stop skipped and a check whose input is unavailable are both `not_evaluated`, never `pass`; do not infer an unobserved check passed. `references/assessment-guide.md` says which of them the saved `checks` write out and where a stopped row's list ends.

"Section 5" in this table is `references/costing.md`, which defines the metric-gap reasons, the fee function and both value objects.

The thresholds are the fixed source settings listed in stage 3 of `SKILL.md`. The constructor supplies `50` explicitly, so generic `MINIMAL_SAVINGS` environment defaults do not override it. No tenant-config setting is consumed by this validator; native CUR discovery separately uses the tenant resource-cost threshold.

Rule helpers are exact: enabled means `Status !== 'Disabled'`. A rule without `Filter` is global unless its deprecated rule-level `Prefix` is nonempty. With `Filter`, a truthy `Prefix` or any non-nullish `Tag` makes it nonglobal; otherwise it is global when there is no `And`, or when `And` has neither a truthy `Prefix` nor nonempty `Tags`. Size bounds alone remain global. Filter takes precedence over deprecated Prefix. Keep rule IDs only when non-nullish. `globalRuleCount` counts all enabled global rules.

An early expiration has `Days > 0 && Days < 31`, or a `Date` strictly before UTC midnight(asOf)+31 days. An early transition targets `GLACIER`, `DEEP_ARCHIVE` or `GLACIER_IR`, and has defined `Days < 31` (day 0 counts), or a date before that same boundary. Past dates still count; date equality at the boundary does not. The native check does not inspect noncurrent-version actions or prefix/tag-scoped actions. Its conflict-report predicate uses the same enabled/global/current-version rules.

For order 8, a denied IT-configuration read emits **only** `IntelligentTieringConfigurationNotChecked`, value `{error}`, passed=true; do not emit a false clean archive check. Otherwise emit `NoProblematicIntelligentTieringConfiguration`, value `{intelligentTieringConfigurationCount,enabledArchiveAccessTiers}`, passed=true. Consider configurations with `Status === 'Enabled'`; collect unique `ARCHIVE_ACCESS` and `DEEP_ARCHIVE_ACCESS` tier names in first-seen order. If any exist, set/preserve a warning naming the bucket and those tiers (3–5 hour and 12+ hour retrieval, respectively). This warns even for a scoped configuration. It is not a native rejection. Preserve existing supplied warnings when none is added.

In native execution, a completed history lookup provides order 1. Standalone mode leaves that framework row not_evaluated; resource-level eligibility can still be assessed from orders 2–12, while full-framework equivalence remains unknown. Do not call this a native approval. After order 10, finalize undecided non-stopped resource-check rows as approved iff no validation failed; attach successfully read tags only to approved rows. Then calculate/report savings for **every row**, including stopped or rejected rows, as `references/costing.md` specifies. Orders 11–12 subsequently run on all rows without `stopProcessing` (including an ordinary failure at order 6 or 7); approved rows have stopProcessing cleared by the base class. A non-finite saving adds `reason:"annual-savings-not-finite"`; MaximumSavings adds `"annual-cost-not-finite"` if savings is finite and annualCost is not. The actual comparisons remain `>` and `<=`; do not reinterpret a non-finite calculation as a meaningful amount. Source rejection clears fixer parameters but retains calculation/report data. A rendered recommendation report exists only for approved rows.

Native per-item exceptions emit fail-fast `Exception` with type Other and `{context,error,errorName,stack}`; retain the complete error locally. Batch IAM denial replaces batch results with error rows in the production framework; a standalone skill records the read failure and affected scope without pretending to mutate CloudFix recommendations. Other batch exceptions fail the assessment. In qualitative mode, leave economics-dependent checks unassessed rather than manufacture native pass/fail rows or finalized approval. Clearly separate known rejection, skipped-after-fail-fast and unassessed-for-missing-evidence.

**Exact per-item exception contract.** A fault caught inside a wrapped validation callback uses `context:"Validation error: "`. A fault caught inside parameter population uses `context:"Error while populating parameters: "`. Both literal strings end with one space; retain it. The row is `{name:"Exception",type:"Other",approved:false,value:<serialized {context,error,errorName,stack}>}` and sets the item `approved:false,stopProcessing:true`. For an actual Error, `error` is its message and `errorName` its name; for a thrown non-Error, `error=String(thrownValue)`, `errorName:null`, `stack:null`. Preserve the observed stack when available under the native serialization limits, otherwise null; never invent a stack or infer an unrecorded error class. Preserve full diagnostics separately. Only an evidenced thrown fault at the stated boundary produces this row: a missing unattempted read or an ordinary failed validation is not an Exception. Later source stages retain their existing skip, savings and cleanup rules.

A per-bucket metric fault rethrown inside the object-metrics check uses the validation context. Initial parameter assignment and approved tag population use the parameter context. IAM/request failures outside callbacks retain their batch boundary; explicitly swallowed lifecycle/IT-configuration/tag reads keep their existing outcomes. Do not turn those swallowed reads into Exception rows.

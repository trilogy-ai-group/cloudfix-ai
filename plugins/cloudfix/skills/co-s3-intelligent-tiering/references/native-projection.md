# Optional outputs: replay packet and native-shaped projection

Read this only when the user explicitly asks for a replay packet or for output in the finder's own native shape. Neither is part of a normal run: the mandatory outputs are the evidence files, `assessment.json` and the customer report. Nothing here changes a decision or an amount.

## Replay packet

When requested, save a replay packet `{run_metadata,run_context,evidence}` beside `assessment.json`. Create shared `run_metadata` before collection: `accountId`, `region`, `asOf`, `scope`, `skillRevision` (selected commit or file hash), `economicsMode`, `configuration`, `configuration_overrides`, `run_classification`, `experiment`. Defaults are the source constants in this skill, overrides `{}`, classification `standard`, experiment `null`. Repeat this complete metadata in the replay packet and its request/calculation records. `evidence` contains complete resource rows, selected bucket IDs, raw operation records `{service,operation,accountId,region,input,output|error,observedAt}`, every page, CUR query/mapping/raw rows or supplied-cost provenance, any public catalog/selected dimension evidence and model inputs, parsed metrics with timestamps, normalization notes, constants and calculation traces. In Cost Explorer `billing`, `economicsMode` is `cost-explorer` and the evidence includes the complete `cost_explorer_effective_rate` record. Preserve original supplied packets and failed attempts unchanged. Retain complete experiment fields in every saved input and result.

## Native-shaped projection

When an exact native-shaped projection is requested, retain it separately as `native_equivalent_projection` with `resource`, `validations:[{name,type,approved,value}]`, `resourceTags`, `finderReportData`, `otherImpactedNodeIds`, applicable `fixerParameters`, determinable `approved`/`stopProcessing`, and supported native `annualSavings`, and reference it from the finding's `source_output:{kind:"guided_projection",evidence_ref}`. The `checks` array in `assessment.json` is the explanatory ledger, not an alias for the serialized native field. Unknowns remain explicit outside native-shaped rows. A reconstruction is never labelled `native`. `source_output` is set only when this projection was actually saved; leave it out otherwise.

Native validation `value` is JSON **text**, with special numeric/date handling: nonfinite numbers become `"NaN"`, `"Infinity"` or `"-Infinity"`; an invalid Date becomes `"Invalid Date"`; valid dates become ISO text and undefined object keys are omitted. Map, Set or Error objects in a value cause an error, not `{}`. Native serialization warns above 8,192 UTF-8 bytes and, only above 65,536 bytes, emits JSON text for `{truncated:true,originalBytes:<full JSON UTF-8 byte count>,head:<first 8,192 UTF-8 bytes without splitting a code point>}`. Native exception `stack` keeps at most 4,096 UTF-8 bytes on a code-point boundary. These bounds describe the **native-shaped projection only**: retain the complete original value, diagnostics and stack in private evidence and references, and verify that reviewers/replay consumers read them. Never apply these bounds to evidence, findings, caller metadata or the assessment ledger. If complete records cannot be preserved and delivered, return an explicit error rather than a partial success.

## Native display fields

Native display fields use JavaScript `toFixed`: costs/savings and storage GB to 2 decimals; object/candidate counts to 0; averageObjectSizeKb to 1; smallObjectShare*100 to 1. Native report data includes `bucketName`, `annualCost`, `annualSavings`, `projectedAnnualCost`, `hasArchiveAccessWarning`, `problematicTiersMessage`, `intelligentTieringReadFailure`, complete lifecycle rules and compatible/conflicting counts, five storage-profile display fields (`totalStorageGb`, `standardStorageGb`, `infrequentAccessGb`, `glacierInstantRetrievalGb`, `otherStorageGb`), `dataSavings`, `extraSavings`, `grossSavings`, `objectCount`, `candidateObjectCount`, `existingMonitoringFee`, `averageObjectSizeKb`, `monitoringFee`, `transitionCharge`, `firstYearNetSavings`, `smallObjectSharePercent`. Keep the original numeric fields too. Missing estimate-derived display fields stay absent, not zero.
